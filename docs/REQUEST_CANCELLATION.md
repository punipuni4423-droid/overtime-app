# 勤怠時間入力と申請の取り下げ・削除

## 変更内容

- 勤怠時間修正の出勤・退勤・休憩時刻を `HH:mm` で直接入力できる。1分単位、翌日を含む `00:00`〜`47:59` に対応し、不正値・未入力では送信しない。
- 取り下げ・削除は操作直前の詳細を取得し、本人・対象・状態を確認する。一覧が保持するステップ番号を送信しない。
- 承認待ちは取り下げ後の下書き状態を確認して削除し、削除後の詳細404を確認してから成功とする。差戻し・下書きは直接削除できる。承認済みなどは中止する。
- Web操作が必要な経路では同じ詳細画面で取り下げ・削除する。ボタンが更新されない場合に限り一覧へ戻って対象を開き直す。書き込み後の無条件再クリックは行わない。
- 同じ事業所・申請種別・IDの同時操作を防止。更新競合の取り下げだけ最新ステップで1回再試行し、削除の通信断・403・429では再送しない。
- 進行状況と「取り下げ済み・削除未完了」を表示し、失敗対象の選択を残す。一覧の再取得が終わるまで操作ボタンを無効にする。

## 検証

2026年10月1日、利用者が明示確認した自己承認経路の残業申請4件で、同じ詳細から削除する方式と一覧へ戻る方式を比較した。全4件の削除を詳細404および対象日の一覧で確認済み。承認は実行していない。

計測が成立した同じ詳細方式は約1.6秒・1.7秒、一覧経由は約3.2秒だった。一覧経由の残る1件は検証スクリプトの表示判定を修正して後片付けしたため、時間比較から除外した。少数事例なので長期的な失敗率は評価できない。上記は操作方式の実環境比較であり、変更後のIPC実装を追加の実申請で再試験したものではない。

回帰確認:

```powershell
npm run build
node scripts/check-request-cancellation.mjs
```

レンダラー専用Viteを `http://127.0.0.1:5186` で起動した状態で次も実行する。

```powershell
node scripts/check-work-time-input.mjs
node scripts/check-cancellation-ui.mjs
```

回帰テストはAPIを模擬し、ブラウザーの外部通信を遮断する。実freeeへの申請作成・承認・削除は行わない。休日出勤はWeb詳細の本人・形式を検証できない場合に操作を中止する。休日出勤を含む残業以外の実データ操作は今回の実環境試験の対象外。

実データの識別子、認証情報、スクリーンショット、実環境専用スクリプトはGitに含めない。
